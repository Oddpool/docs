---
title: "List matched events"
description: "Page live or historical matched events, filtered by venue pair and fungibility."
api: "GET https://api.oddpool.com/reference/events"
---

Page through matched events. Each item is a full event, the same shape as [Resolve a venue ticker](/institutions/reference-data/events/lookup#response).

<Tip>
Pass `active=true` for events with markets still trading today. Without it you get the full corpus, which is mostly long-settled events.
</Tip>

## Query parameters

<ParamField query="active" type="boolean">
  `true` returns only events with at least one venue market still trading. Recommended for live trading. Omit for the full historical corpus.
</ParamField>
<ParamField query="subject_domain" type="string">
  Category filter, sourced from Kalshi (e.g. `Sports`). Free text.
</ParamField>
<ParamField query="venue_pair" type="string">
  Limit to events both venues list, e.g. `kalshi,polymarket`. Order doesn't matter. Required to use the three fungibility filters below.
</ParamField>
<ParamField query="fungible" type="boolean">
  Needs `venue_pair`. `true` returns only events whose sides are fully interchangeable on that pair (`basis_class=identical` and `outcome_universe=identical`).
</ParamField>
<ParamField query="basis_class" type="string">
  Needs `venue_pair`. Filter that pair's settlement agreement: `identical`, `settlement_window`, or `settlement_source`.
</ParamField>
<ParamField query="outcome_universe" type="string">
  Needs `venue_pair`. Filter how the outcome lists line up: `identical`, `partial`, or `disjoint`.
</ParamField>
<ParamField query="classified_since" type="datetime">
  ISO 8601. Returns only events re-evaluated on or after this time — pass your last sync time to fetch just what changed.
</ParamField>
<ParamField query="limit" type="integer" default="50">
  Items per page (1–2000).
</ParamField>
<ParamField query="cursor" type="string">
  The `next_cursor` from the previous response.
</ParamField>

<Info>
`basis_class`, `outcome_universe`, and `fungible` describe how two venues settle relative to each other. Their meanings are documented on the [event response](/institutions/reference-data/events/lookup#response).
</Info>

## Request

<CodeGroup>
```bash cURL
curl -H "X-API-Key: your_api_key" \
  "https://api.oddpool.com/reference/events?venue_pair=kalshi,polymarket&fungible=true&active=true&limit=100"
```
```python Python
import requests

r = requests.get(
    "https://api.oddpool.com/reference/events",
    headers={"X-API-Key": "your_api_key"},
    params={"venue_pair": "kalshi,polymarket", "fungible": "true", "active": "true", "limit": 100},
)
page = r.json()
```
</CodeGroup>

## Response

<ResponseField name="items" type="object[]">
  A page of events, each the full shape from [Resolve a venue ticker](/institutions/reference-data/events/lookup#response).
</ResponseField>
<ResponseField name="next_cursor" type="string | null">
  Pass as `cursor` to get the next page. `null` on the last page.
</ResponseField>

```json
{
  "items": [
    { "oddpool_id": "OPI-OO4GBEZJ", "title": "Gremio vs Corinthians", "...": "full event" }
  ],
  "next_cursor": "eyJpZCI6MTI4NDQ0fQ"
}
```

## Paging

Follow `next_cursor` until it's `null`:

```bash
curl -H "X-API-Key: $KEY" "https://api.oddpool.com/reference/events?active=true&limit=100"
curl -H "X-API-Key: $KEY" "https://api.oddpool.com/reference/events?active=true&limit=100&cursor=<next_cursor>"
```

For incremental sync, store the largest `classified_at` you've seen and pass it as `classified_since` next time. `classified_at` moves when an event is re-evaluated (new outcome, settlement reclassified), not on price or volume changes.
