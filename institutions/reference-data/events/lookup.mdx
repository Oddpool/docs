---
title: "Resolve a venue ticker"
description: "Turn a Kalshi or Polymarket id into the matched event, with every outcome and venue side."
api: "GET https://api.oddpool.com/reference/events/lookup"
---

Give this endpoint a Kalshi or Polymarket id and it returns the matched event: every venue that lists it, every outcome, the entity each outcome refers to, and the venue ticker you trade on each side.

Kalshi input can be an event ticker or a market ticker (a market ticker resolves to its parent event). Polymarket input can be a conditionId, event slug, or numeric event id.

## Query parameters

Pass either `oddpool_id`, or `venue` + `id`.

<ParamField query="venue" type="string">
  `kalshi`, `polymarket`, or `polymarket_us`. Required when you pass `id`.
</ParamField>
<ParamField query="id" type="string">
  The venue's id. Kalshi: event or market ticker. Polymarket: conditionId (`0x…`), event slug, or numeric event id.
</ParamField>
<ParamField query="oddpool_id" type="string">
  An Oddpool event id (`OPI-XXXXXXXX`) instead of a venue id.
</ParamField>

## Request

<CodeGroup>
```bash cURL
curl -H "X-API-Key: your_api_key" \
  "https://api.oddpool.com/reference/events/lookup?venue=kalshi&id=KXBRASILEIROGAME-26MAY30GPACOR-GPA"
```
```python Python
import requests

r = requests.get(
    "https://api.oddpool.com/reference/events/lookup",
    headers={"X-API-Key": "your_api_key"},
    params={"venue": "kalshi", "id": "KXBRASILEIROGAME-26MAY30GPACOR-GPA"},
)
event = r.json()
```
</CodeGroup>

## Response

<ResponseField name="oddpool_id" type="string">
  The event id (`OPI-XXXXXXXX`). Stable for the life of the event.
</ResponseField>
<ResponseField name="title" type="string">
  Display title, e.g. `Gremio vs Corinthians`.
</ResponseField>
<ResponseField name="subject_domain" type="string | null">
  Category, sourced from Kalshi (e.g. `Sports`). Free text, may be `null`.
</ResponseField>
<ResponseField name="classified_at" type="string | null">
  ISO 8601 timestamp of the last time this event was re-evaluated (outcome added, settlement reclassified). Use it as the high-water mark for incremental sync via `classified_since`. Does not move on price or volume changes.
</ResponseField>

<ResponseField name="venue_listings" type="object[]">
  The event as each venue lists it — one entry per venue.
  <Expandable title="fields">
    <ResponseField name="oddpool_id" type="string">Listing id (`OPL:…`).</ResponseField>
    <ResponseField name="venue" type="string">`kalshi`, `polymarket`, or `polymarket_us`.</ResponseField>
    <ResponseField name="venue_event_id" type="string">The venue's id for the parent event.</ResponseField>
    <ResponseField name="venue_question" type="string | null">The venue's raw question text at mapping time.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="venue_pairs" type="object[]">
  Where the venues agree on settlement — one entry per pair of venues that both list the event. This is event-level agreement; per-outcome fungibility is on each outcome below.
  <Expandable title="fields">
    <ResponseField name="venue_a / venue_b" type="string">The two venues, precedence-ordered (`kalshi` < `polymarket` < `polymarket_us`).</ResponseField>
    <ResponseField name="venue_a_event_id / venue_b_event_id" type="string">Each venue's event id for this pair.</ResponseField>
    <ResponseField name="basis_class" type="string | null">
      Whether the two venues settle on the same thing at the same time.
      - `identical` — same anchor, same authority, within 24h.
      - `settlement_window` — settlement times differ by more than 24h, or the venues anchor on different stages (election day vs. certification).
      - `settlement_source` — same value read from two different authorities (e.g. National Weather Service vs. Weather Underground).
    </ResponseField>
    <ResponseField name="outcome_universe" type="string | null">
      How much the two venues' outcome lists line up.
      - `identical` — every outcome pairs 1:1.
      - `partial` — some pair, at least one is one-sided.
      - `disjoint` — none pair.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="outcomes" type="object[]">
  Each named answer on the event.
  <Expandable title="fields">
    <ResponseField name="oddpool_id" type="string">Outcome id (`OPO:…`).</ResponseField>
    <ResponseField name="label" type="string">Display label — an entity name, `Yes`, a bucket descriptor, etc.</ResponseField>
    <ResponseField name="outcome_kind" type="string">
      The outcome's shape.
      - `binary` — single Yes/No.
      - `multi_class_named` — N named entities, one wins.
      - `range_bin` — a bucketed numeric interval.
      - `threshold_above` / `threshold_below` — a cumulative ≥ N / ≤ N ladder.
      - `point_mass` — an exact value.
      - `spread` — a handicap on a line.
      - `will_happen_by_date` — a time-bound Yes/No with a deadline.
    </ResponseField>
    <ResponseField name="outcome_params" type="object">
      Structured parameters for numeric and time-bound kinds; `{}` for `binary` and `multi_class_named`. See the shapes below.
    </ResponseField>
    <ResponseField name="entity" type="object | null">
      The team / person / party this outcome refers to, or `null` for non-entity outcomes like `Tie`. Same shape as the [entity endpoints](/institutions/reference-data/entities/lookup) — `oddpool_id`, `kind`, `canonical_name`, `aliases`, `wikidata_qid`, `metadata`.
    </ResponseField>
    <ResponseField name="venue_listings" type="object[]">
      The tradeable side of this outcome on each venue — the ids you subscribe to.
      <Expandable title="fields">
        <ResponseField name="oddpool_id" type="string">Listing id (`OPL:…`).</ResponseField>
        <ResponseField name="venue" type="string">`kalshi`, `polymarket`, or `polymarket_us`.</ResponseField>
        <ResponseField name="venue_market_id" type="string">
          The venue's native id for this side — what you trade on.
          - Kalshi: the market ticker.
          - Polymarket binary: the `conditionId`.
          - Polymarket atomic-binary: `conditionId#<index>` — split on `#` to recover the conditionId, then subscribe with the tokens below.
        </ResponseField>
        <ResponseField name="venue_yes_token / venue_no_token" type="string | null">Polymarket CLOB token ids for each side. `null` on Kalshi.</ResponseField>
        <ResponseField name="venue_event_id" type="string | null">The venue's parent-event id.</ResponseField>
        <ResponseField name="venue_question" type="string | null">The venue's raw question text at mapping time.</ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="venue_pairs" type="object[]">
      Whether this outcome's two venue sides are one tradeable instrument — one entry per pair of venues that both list it.
      <Expandable title="fields">
        <ResponseField name="venue_a / venue_b" type="string">The two venues.</ResponseField>
        <ResponseField name="fungible" type="boolean">
          `true` when the sides settle identically (event `basis_class` is `identical` and `divergence_axes` is empty) — you can treat them as one instrument for quoting, hedging, and risk. The one-glance answer.
        </ResponseField>
        <ResponseField name="divergence_axes" type="string[]">
          When not fungible, how the two sides settle differently. Empty means no divergence.
          - `timing` — same answer, fixed at different moments (the event vs. a later certification / swearing-in).
          - `source` — same value from two different authorities.
          - `condition_scope` — differ on an edge case, e.g. cancellation / postponement policy, or what counts toward the condition. Common on sports and entertainment.
        </ResponseField>
        <ResponseField name="divergence_reason" type="string | null">One sentence naming the specific case, when `divergence_axes` is non-empty.</ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<Accordion title="outcome_params shapes">
Numeric kinds carry `outcome_params.bucket`; `will_happen_by_date` carries `outcome_params.deadline`. Rely on `bucket` / `deadline` and ignore any unknown sibling keys.

```jsonc
// range_bin — half-open numeric interval
"outcome_params": { "bucket": { "shape": "discrete_range",
  "lo": 0.0, "hi": 50000.0, "lo_inclusive": true, "hi_inclusive": false, "units": "count" } }

// threshold_above — cumulative ladder, open upper bound
"outcome_params": { "bucket": { "shape": "cumulative_threshold",
  "lo": 25.0, "hi": null, "lo_inclusive": false, "hi_inclusive": null, "units": "bps" } }

// point_mass — exact value
"outcome_params": { "bucket": { "shape": "point_value",
  "lo": -25, "hi": -25, "lo_inclusive": true, "hi_inclusive": true, "units": "bps" } }

// spread — handicap on a line; line and side are spread-only
"outcome_params": { "bucket": { "shape": "spread", "line": 1.5, "side": "favorite",
  "lo": 1.5, "hi": null, "lo_inclusive": false, "hi_inclusive": null, "units": "pts" } }

// will_happen_by_date
"outcome_params": { "deadline": { "iso8601": "2027-01-01", "inclusive": false } }
```
</Accordion>

## Errors

Returns `404` when no match exists for the id:

```json
{ "detail": { "error_code": "EVENT_NOT_FOUND", "error": "no_canonical_match",
              "venue": "kalshi", "id": "KXNONEXIST-99" } }
```
