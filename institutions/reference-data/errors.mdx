---
title: "Errors"
description: "The error envelope and the stable error_code values for programmatic handling."
---

Error responses use FastAPI's standard envelope: a `detail` field whose value is either a short string (for authentication failures) or a structured object containing `error_code` plus context fields.

```jsonc
// 401 / 403 — string detail
{ "detail": "Invalid API key" }

// 400 / 404 — structured detail
{ "detail": { "error_code": "EVENT_NOT_FOUND",
              "error": "no_canonical_match",
              "venue": "kalshi", "id": "KXNONEXIST-99" } }
```

## Status codes

| Status | `detail` shape | When |
|--------|----------------|------|
| `400` | structured | Invalid or missing query parameter. |
| `401` | string | Missing or unknown API key. |
| `403` | string | Key recognized but without access to this endpoint, or trial expired. |
| `404` | structured | No canonical event or entity matches the identifier. |

## Error codes

For `400` and `404`, `detail.error_code` is a stable value safe to branch on programmatically. `detail.error` is a shorter machine-friendly tag, and the remaining fields echo the input that failed to resolve.

| `error_code` | Meaning | Echoed context |
|--------------|---------|----------------|
| `BAD_REQUEST` | A required parameter was missing or a combination was invalid. | `error` |
| `EVENT_NOT_FOUND` | No canonical event maps to the identifier. | `venue` + `id`, or `oddpool_id` |
| `ENTITY_NOT_FOUND` | No canonical entity maps to the identifier. | `oddpool_id`, `wikidata_qid`, or `kind` + `name` |

```json
{
  "detail": {
    "error_code": "BAD_REQUEST",
    "error": "must_supply_oddpool_id_or_venue_and_id"
  }
}
```
