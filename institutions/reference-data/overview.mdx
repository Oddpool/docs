---
title: "Reference Data API"
description: "One canonical identifier per cross-venue event, outcome, and entity — with the venue-side ids to trade each side."
---

Kalshi, Polymarket, and other prediction-market venues each issue their own tickers, IDs, and question text for the same underlying event. The Reference Data API resolves them to a single canonical identifier — one ID per cross-venue event, one ID per named outcome, one ID per real-world entity the event references — and returns the venue-side identifiers you need to subscribe to live prices on each side.

Mappings are produced algorithmically and confirmed through human review. You get a single trustworthy reference layer to build against, without standing up a per-venue normalization stack.

The registry is explicit about where venues disagree. Two classification axes on every event (`basis_class`, `outcome_universe`), plus per-outcome `divergence_axes` and a one-sentence rationale, distinguish truly fungible cross-listings from structurally divergent ones — so you can route on the difference instead of discovering it at settlement.

Every canonical entity carries a Wikidata Q-ID, a stable cross-reference to FEC, bioguide, LEI, sports-reference, MusicBrainz, and other authoritative identifier systems. Prediction-market data joins the broader structured-data graph without bespoke entity matching on your side.

## Base URL

```text
https://api.oddpool.com
```

Every endpoint accepts `X-API-Key: oddpool_<key>` and returns JSON. See [Authentication](/institutions/reference-data/authentication).

## Quickstart

Resolve a Kalshi or Polymarket native id to the canonical event:

```bash
curl -H "X-API-Key: $KEY" \
  "https://api.oddpool.com/reference/events/lookup?venue=kalshi&id=KXSB-27-ARI"
```

Fetch a canonical event by Oddpool ID:

```bash
curl -H "X-API-Key: $KEY" \
  "https://api.oddpool.com/reference/events/OPI-U3PW57WP"
```

Page through canonical events whose venue markets are still trading today (recommended default for live consumers):

```bash
curl -H "X-API-Key: $KEY" \
  "https://api.oddpool.com/reference/events?active=true&limit=100"
```

Look up a canonical entity by Wikidata QID, or search by substring:

```bash
curl -H "X-API-Key: $KEY" \
  "https://api.oddpool.com/reference/entities/lookup?wikidata_qid=Q22686"

curl -H "X-API-Key: $KEY" \
  "https://api.oddpool.com/reference/entities?q=lakers&kind=team"
```
